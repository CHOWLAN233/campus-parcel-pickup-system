# 作业要求与内部需求对齐

## 必须同时满足

| 来源 | 要求 | 项目处理方式 |
| --- | --- | --- |
| 作业简报 SA3 | 构建 Web 登录/注册 + 1–2 个额外功能 | 登录/注册 + 时段预约/容量限制 + 邀请码代取 |
| 作业简报 SA3 | Username 必填、唯一并有长度限制 | 以 Student ID 作为可见 Username，使用预置虚构学号白名单并设置最小/最大长度 |
| 作业简报 SA3 | Email 格式正确且唯一 | 注册表和 `users.email` 增加格式与唯一性服务端校验；仅使用虚构 Email |
| 作业简报 SA3 | 密码强度、Confirm Password、哈希存储 | 服务端验证长度/数字/特殊字符和两次输入一致；数据库只存 bcrypt 哈希 |
| 内部 SRS v1 | Student ID + Password 登录 | 登录标识仍使用 Student ID，不改为 Email 登录 |
| 内部 SRS v1 | 时段容量不可超卖 | PostgreSQL 事务与集成/并发测试保证 |
| 内部 SRS v1 | 邀请码代取且最多两名他人 | 作为第二个额外功能；数据库约束与服务端边界校验共同实现 |
| 作业简报 SA3 | 至少 4 个真实、可复现的预设缺陷 | 只在隔离测试分支/环境中设置，答案记录在 `docs/private/` 并单独上传 Moodle |
| 作业简报 SA3 | Selenium POM 与 JMeter | 分别保存在 `tests/selenium/` 与 `tests/jmeter/`，保留日志、截图和结果解释 |

## 仍需小组确认

内部 SRS 中标为“待确认”的规则必须在编码和编写预期结果之前定稿。若未确认，暂采用 SRS 建议值，但需在测试计划中明确标记为假设。
